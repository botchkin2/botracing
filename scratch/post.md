FINDINGS (emulator, Compare 19 laps, frames in 7 s, 3 runs; baseline 65-94 frames = ~10-13 fps):
- UI thread is 66% busy, JS thread 55%. simpleperf: 60% of UI-thread time is Canvas.drawPath called from react-native-svg RenderableView.draw (SvgView.onDraw inside the display-list update). Render thread is ~2 ms, GPU p99 ~19 ms. So it is path drawing on the UI thread, not raster and not JS alone.
- Hide map: 87-98 frames. No series lines at all (map shown): 59-106, no gain. No lines AND no map: 144-164 frames (~2x). So lines and map each cost about half of the path drawing; fixing only one shows little. Both must shrink.
- No gain: dropping vectorEffect=non-scaling-stroke (draw p50 65-79 vs 66-85); chunks of width/4 instead of width (drawn geometry 3 windows -> 1.5; 80-87 frames, same as baseline). So raw path volume of the series lines is not the lever either; per-Path/per-frame redraw of the whole Svg is.
- Caveat: 76% of UI-thread samples are kernel (read_hpet, IPI/TLB shootdown, clear_page): emulator-inflated memory/timer cost; the ranking between variants still holds, absolute ms do not.
