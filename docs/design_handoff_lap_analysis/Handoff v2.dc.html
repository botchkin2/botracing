Handoff v2 · answers to the feedback log

Missing and unclear items, designed

Each block is labelled with its log number: M = Missing, W = Wrong or unclear, B = Decided during the build. The build decisions are adopted as the design, and the phone and desktop prototypes have been updated to match (see V8). The README's "v2" section has the same content as text.

M1

Racing lines on the real track map

The map panel keeps its Follow / Track switch and adds Satellite, disabled until it ships. The OSM outline is drawn as a band with edges, the pit lane is a thinner band, and georeferenced lap traces sit on top in lap colors. Section boundaries are ticks across the track, labelled S1–S5 on the inside, and corner numbers are small on the outside. The quality chip shows where the outline came from. OSM attribution is always visible whenever OSM data is drawn. The track shape here is the synthetic sample, so the layout is illustrative and every rule is real.

Adopted. The grid, map badges, strip and position row use sections, and apex lines keep corner numbers. With 5 columns each cell gets about 60 pt, so there's room for two decimals and a sign in 11 pt. The header shows which corners each section covers.

M3

Loading, offline and error states

The rules are to show cached data first, never block the screen for data that's already on the phone, and to say plainly what failed and what still works. Status banners are neutral because amber is reserved for selection. Error text says what happened, not what the user did.

M4 · W2 · B1 · B2

Series and event, with real names at 375 pt

Events group sessions under a thin header inside each day, and sessions without an event list normally. The session type lives in the R, Q or P badge (B2). Line 1 is the short track or layout name, which never truncates. Line 2 is the car model then the time; the car name is what truncates, and the time never does. Event headers truncate the event name and keep the series chip. The Session header carries the full names (B1).

V8

Build decisions adopted

B1 · B2Car model first, team second. The session type lives in the badge. Applied to Sessions (phone and desktop rail) and the Session header.
B3 · B4Laps are numbered L1 up in driving order. OFF shows from 1.0 s, and HIT has no g value. The detail panel reads "Impact recorded, possible damage." Applied to the tags and the detail copy.
B5 · B6 · desktop tiersThree tiers: 1280 and up uses D1–D3; 900–1279 uses the build's two-column layouts (360 left column, flexible main, charts at 1.4× height, Edit charts as a right sheet); below 900 uses the phone. This replaces "fall back to phone".
B6 · B8D1 drops Top km/h. The Stint column is 34 pt. Fall-off shows the stored trend with no interval, and is left blank where the session has no data. The rail search and chrome uploader status are removed. D2 has Copy link only. D3 defaults to the current selection, with an "All comparable laps" toggle. All of this is applied in Desktop Screens.
B7Sections S1–S5 in the grid, badges, strip and position row, and corner numbers on apex lines ("C8 apex"). Shown above.
B9In Time mode the x axis is reference elapsed time, and metre gridlines map through it, so they are wide on straights and tight in corners. At the start/finish line the window keeps its size, with a blank lead-in and the line marked. Distance mode stays linear. This is now in the README; the prototype still draws metres.
B10Corners with no braking show "—" for brake point. When the apex falls at the section entry or exit, the label reads "apex at entry, 1,050 m". Applied to the corner explainer.
