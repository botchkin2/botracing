# Lap API

One Cloud Function, `lmuApi`, behind Hosting at `/api/lmu`. It reads only; the PC uploader (`tools/sessions/sync.mjs`) writes. Storage layout: `docs/STORAGE.md`.

## v2: for the redesigned screens

| Route                                      | Returns                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /sessions?age=<days>&track=<trackId>` | `{items, total}`: sessions newest first (default 30 days). Per item: track, car, type, start/end, weather, lap and comparable counts, best/median/spread, `stints`, `bestLapId`, and `series`/`eventId` when known.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `GET /sessions/{id}`                       | The whole session doc: `lapTable`, `stints`, `consistency` (overview, pace trend, off-pace laps, corners, damage checks, thresholds), `band` pointer, `trackMapSource`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `GET /sessions/{id}/laps`                  | `{items}`: every lap doc in driving order. Time, sectors, stint, `excluded` and why, off-track and past-edge seconds, impact, compound, wetness, per-section facts with `parts` per corner, and `trace.path`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `GET /sessions/{id}/band`                  | Median and p10/p90 of speed, throttle and brake every `stepM` metres over the comparable laps.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `GET /sessions/{id}/map`                   | The track's corner map (sections with their corners), plus, when fitted, `georef`, `quality` (`good`/`fair`/`poor`), `qualityNote`, `attribution` and the OSM `outline` (GeoJSON). Draw on a real basemap only when `quality` isn't `poor`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `GET /sessions/{id}/surface` | The session's track's measured surface (`tools/sessions/surface.mjs`, rules in `src/analysis/trackSurface.ts`): `{v, stepM, lengthM, sessions, bins}`, one entry per 10 m along the lap with sums of the centre path (`sx`, `sy` over `n` samples in `laps` laps) and of the left and right edge (`sL`/`nL`/`lapsL`, `sR`/`nR`/`lapsR`), in the game's own metres before any georef (place them like a lap). About 12 KB gzipped for a track. Sent gzipped, `no-cache` (it grows as sessions are folded in). 404 when the track has none yet. |
| `GET /sessions/{id}/field/{hash}`          | Every car at 5 Hz, when the recorder (`tools/capture`) was running: `{v, hz, et0, tDs, cars, lapDistDm, pathLateralDm, xDm, zDm, yawCrad, place, laps, inPits, flag}`. `cars` is `[{i, class, vehicle, player}]`: no names or car numbers; `vehicle` is the car model, or null when the recorder had none. `tDs` is tenths of a second from `et0` (the session clock). Per car and update, the five position arrays are **deltas** (decimetres, except `yawCrad`) (a running sum gives the value; `null` means the car was absent, keeping its last value). x/z are the sim's world coordinates, not the trace Lat/Lon. `yawCrad` is the car's heading in centiradians (0.01 rad), in the same convention as `atan2(Δx, Δz)` of consecutive x/z: 0 along +z, +157 along +x, wrapping at ±314; its running sum is the wrapped heading, so a delta of about ±628 is the wrap, not a turn. From the game's orientation matrix (`atan2(mOri[2].x, -mOri[2].z)`); on the Daytona capture it is within 0.012 rad (median) of the direction of travel above 10 m/s. Files with `v: 1` have no `yawCrad`; treat it as absent. At a standstill it is the car's real heading, not the direction it last moved. Use `field.hash` from the session doc: under `/field/{hash}` the response is immutable (a changed field has a new hash; an old hash returns 404). Plain `/field` returns the current one with `no-cache`. Sent gzipped (`Content-Encoding: gzip`). 404 when the session has no `field`. The function returns up to 32 MB, about a 16-hour race. |
| `GET /sessions/{id}/corners/{n}/laps/{hash}` | Every lap's window around corner `n` (the numbers in `session.slices.corners`), cut by the uploader (`tools/sessions/cornerSlices.mjs`): `{v:1, corner, apexM, lengthM, stepM, digits, windowM, laps:[{id, gridFromM, timeS, lat, lon, samples}]}`. `windowM` is `[apex-350, apex+200]` clipped to the lap; distances are metres along the lap in the app's frame. `samples` has, per channel (`speedKph`, `throttlePct`, `brakePct`, `steeringPct`, `pathLateralM`, `trackEdgeM`), `{d, v}`: the channel's **recorded samples** inside the window plus one either side, at their own rates (a 50 Hz pedal is not repeated to 100 Hz; a channel the lap lacks is empty). Every array is integers, first value then differences; the value is the running sum divided by `10^digits[name]`. `timeS`, `lat`, `lon` are on the 5 m grid from `gridFromM`. Lap ids are the lap doc ids. Decode with `src/analysis/cornerSlices.ts`. Use `session.slices.hash`: under `/laps/{hash}` the response is immutable (a resync that changes any lap has a new hash; an old hash returns 404); plain `/laps` returns the current one with `no-cache`. Gzipped. 404 when the session has no `slices` or the corner has no file. About 100 to 180 KB for a 44-lap race. |
| `GET /laps/{id}/csv`                       | One lap's 100 Hz trace: `Speed,LapDistPct,Lat,Lon,Brake,Throttle,RPM,SteeringWheelAngle,Gear,OffAsphalt,PathLateral,TrackEdge`. Lat/Lon (10 Hz) and Brake/Throttle (50 Hz) are empty on rows where they recorded no sample. `PathLateral` and `TrackEdge` (analysis version 9, 10 Hz, also empty between samples) are metres from the game's approximate centre path, positive to the right (measured on Road Atlanta: right-hand apexes read +2 to +4 m, left-hand ones −3 to −5 m). `TrackEdge` is the edge on the car's side, not both edges, so it has the lateral's sign and jumps when the car crosses the path. A trace uploaded before version 9 has neither column.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `GET /uploaders`                           | `{items}`: one status per PC uploader (`tools/uploader/`): `hostId` (a short hash of the machine name), `label` (set on the PC, default "Race PC"), `version`, `lmuFound`, `state` (`waiting-for-game`, `in-game`, `syncing`, `retrying`, `error`), `retryAt` (ISO, when the earliest failed session is tried again, else null; state `retrying`), `lastSeenAt`, `lastUploadAt`, `lastSessionId`, `queue`, `progress` `{done, total}` while a sync runs (else null; `phase: "surface"` while the track surfaces are folded in after the sessions, done/total tracks), `sessionsDone`, `lastError` `{at, message, path}` (one line, user folders scrubbed, path relative), `disk` `{captureBytes, freeBytes}`, and `recorder` `{state, gameVersion, layoutOk, layoutReason, lastChunkAt, updatedAt}` or null. Times are ISO.                                                                                                                                                                                                                                                                                                                                                                                     |

Unknown ids return 404. Lat/Lon in traces are the sim's coordinates. Real metres, but placed around a fake origin; apply `georef` (`src/analysis/geo.ts`) to put them on the real map.

## v1 (legacy, for the current screens)

`GET /tracks` and `GET /laps?age=&tracks=&event=` return laps in the old Garage 61-style shape. They go away with the old screens.
