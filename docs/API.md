# Lap API

One Cloud Function, `lmuApi`, behind Hosting at `/api/lmu`. It reads only; the PC uploader (`tools/sessions/sync.mjs`) writes. Storage layout: `docs/STORAGE.md`.

## v2: for the redesigned screens

| Route                                      | Returns                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /sessions?age=<days>&track=<trackId>` | `{items, total}`: sessions newest first (default 30 days). Per item: track, car, type, start/end, weather, lap and comparable counts, best/median/spread, `stints`, `bestLapId`, and `series`/`eventId` when known.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `GET /sessions/{id}`                       | The whole session doc: `lapTable`, `stints`, `consistency` (overview, pace trend, off-pace laps, corners, damage checks, thresholds), `band` pointer, `trackMapSource`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `GET /sessions/{id}/laps`                  | `{items}`: every lap doc in driving order. Time, sectors, stint, `excluded` and why, off-track and past-edge seconds, impact, compound, wetness, per-section facts with `parts` per corner, and `trace.path`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `GET /sessions/{id}/band`                  | Median and p10/p90 of speed, throttle and brake every `stepM` metres over the comparable laps.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `GET /sessions/{id}/map`                   | The track's corner map (sections with their corners), plus, when fitted, `georef`, `quality` (`good`/`fair`/`poor`), `qualityNote`, `attribution` and the OSM `outline` (GeoJSON). Draw on a real basemap only when `quality` isn't `poor`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `GET /sessions/{id}/surface` | The session's track's measured surface (`tools/sessions/surface.mjs`, rules in `src/analysis/trackSurface.ts`): `{v, stepM, lengthM, sessions, bins}`, one entry per 10 m along the lap with sums of the centre path (`sx`, `sy` over `n` samples in `laps` laps) and of the left and right edge (`sL`/`nL`/`lapsL`, `sR`/`nR`/`lapsR`), in the game's own metres before any georef (place them like a lap). About 12 KB gzipped for a track. Sent gzipped, `no-cache` (it grows as sessions are folded in). 404 when the track has none yet. |
| `GET /tracks/{trackId}/map`               | A track layout's map by its id, for any signed-in user (shared app data): the same fields as `/sessions/{id}/map` plus `surfaceRev`, the surface's current validator. `ETag` from the track doc's last write; `Cache-Control: private, max-age=3600`; `If-None-Match` gives a 304 with no body. 404 for an unknown or malformed id (`functions/src/trackMapCore.ts`). |
| `GET /tracks/{trackId}/surface`           | The layout's measured surface by its id: the same gzip as `/sessions/{id}/surface`. `ETag` = `surfaceRev` (stamped on the track doc by `surface.mjs`, so a 304 needs no download); `Cache-Control: private, max-age=300`. 404 when the layout has no surface yet. The app reads only these (thread 1 #3479). The per-session `/map` and `/surface` routes stay until every installed Android build reads these too, then go. |
| `GET /sessions/{id}/field/{hash}`          | Every car at 5 Hz, when the recorder (`tools/capture`) was running: `{v, hz, et0, tDs, cars, lapDistDm, pathLateralDm, xDm, zDm, yawCrad, place, laps, inPits, flag}`. `cars` is `[{i, class, vehicle, player}]`: no names or car numbers; `vehicle` is the car model, or null when the recorder had none. `tDs` is tenths of a second from `et0` (the session clock). Per car and update, the five position arrays are **deltas** (decimetres, except `yawCrad`) (a running sum gives the value; `null` means the car was absent, keeping its last value). x/z are the sim's world coordinates, not the trace Lat/Lon. `yawCrad` is the car's heading in centiradians (0.01 rad), in the same convention as `atan2(Δx, Δz)` of consecutive x/z: 0 along +z, +157 along +x, wrapping at ±314; its running sum is the wrapped heading, so a delta of about ±628 is the wrap, not a turn. From the game's orientation matrix (`atan2(mOri[2].x, -mOri[2].z)`); on the Daytona capture it is within 0.012 rad (median) of the direction of travel above 10 m/s. Files with `v: 1` have no `yawCrad`; treat it as absent. At a standstill it is the car's real heading, not the direction it last moved. Use `field.hash` from the session doc: under `/field/{hash}` the response is immutable (a changed field has a new hash; an old hash returns 404). Plain `/field` returns the current one with `no-cache`. Sent gzipped (`Content-Encoding: gzip`). 404 when the session has no `field`. The function returns up to 32 MB, about a 16-hour race. |
| `GET /sessions/{id}/corners/{n}/laps/{hash}` | Every lap's window around corner `n` (the numbers in `session.slices.corners`), cut by the uploader (`tools/sessions/cornerSlices.mjs`): `{v:1, corner, apexM, lengthM, stepM, digits, windowM, laps:[{id, gridFromM, timeS, lat, lon, samples}]}`. `windowM` is `[apex-350, apex+200]` clipped to the lap; distances are metres along the lap in the app's frame. `samples` has, per channel (`speedKph`, `throttlePct`, `brakePct`, `steeringPct`, `pathLateralM`, `trackEdgeM`), `{d, v}`: the channel's **recorded samples** inside the window plus one either side, at their own rates (a 50 Hz pedal is not repeated to 100 Hz; a channel the lap lacks is empty). Every array is integers, first value then differences; the value is the running sum divided by `10^digits[name]`. `timeS`, `lat`, `lon` are on the 5 m grid from `gridFromM`. Lap ids are the lap doc ids. Decode with `src/analysis/cornerSlices.ts`. Use `session.slices.hash`: under `/laps/{hash}` the response is immutable (a resync that changes any lap has a new hash; an old hash returns 404); plain `/laps` returns the current one with `no-cache`. Gzipped. 404 when the session has no `slices` or the corner has no file. About 100 to 180 KB for a 44-lap race. |
| `GET /laps/{id}/csv`                       | One lap's 100 Hz trace: `Speed,LapDistPct,Lat,Lon,Brake,Throttle,RPM,SteeringWheelAngle,Gear,OffAsphalt,PathLateral,TrackEdge`. Lat/Lon (10 Hz) and Brake/Throttle (50 Hz) are empty on rows where they recorded no sample. `PathLateral` and `TrackEdge` (analysis version 9, 10 Hz, also empty between samples) are metres from the game's approximate centre path, positive to the right (measured on Road Atlanta: right-hand apexes read +2 to +4 m, left-hand ones −3 to −5 m). `TrackEdge` is the edge on the car's side, not both edges, so it has the lateral's sign and jumps when the car crosses the path. A trace uploaded before version 9 has neither column.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `GET /plan?sim=&trackId=&car=[&laps=8]` (also `/api/plan`) | The Plan's one request for a track and car: `{items, truncated}`, the signed-in owner's sessions at that `sim` (`lmu` or `iracing`), `trackId` and car model (`car` is `carModel`, the car without its livery), newest first, at most 500 (`truncated` says it was cut). One Firestore query on `sessions (ownerId, sim, trackId, carModel, startedAt desc)` with a projection of `startedAt`, `sessionType` and `plan`, so no lap doc is read. Each item is `{id, startedAt, sessionType, plan}` with `plan` `{v, fuel, laps, race}` as the uploader wrote it (`docs/STORAGE.md`), or `plan: null` for a session uploaded before the block existed (no data, not zero). `laps` is kept for the newest `laps` sessions (default 8, 0 to 500) and is `null` for older ones, whose fuel limits and race side still come. A missing or bad `sim`, `trackId` or `car` is a 400. `Cache-Control: private, max-age=60` and an `ETag` over the body: within a minute a second open is served from the client's cache, after it a conditional request gets a 304 and no download. |
| `GET /uploaders`                           | `{items}`: one status per PC of the signed-in owner (the tray sends it with `POST /api/upload/heartbeat`; the owner's own only, never another's): `hostId` (a short hash of the machine name), `label` (set on the PC, default "Race PC"), `version`, `lmuFound`, `state` (`waiting-for-game`, `in-game`, `syncing`, `retrying`, `error`), `retryAt` (ISO, when the earliest failed session is tried again, else null; state `retrying`), `lastSeenAt`, `lastUploadAt`, `lastSessionId`, `queue`, `progress` `{done, total}` while a sync runs (else null; `phase: "surface"` while the track surfaces are folded in after the sessions, done/total tracks), `sessionsDone`, `problems` (up to 10 of `{kind: session-failed|sync-crashed|recorder-layout|uploader-stopped|not-seen, at, message (120, user folders, tokens and addresses removed), sessionId?, count?, retryAt?}`; `uploader-stopped` is sent by the tray itself when the uploader exits, with the tray's `version`; `not-seen` is added by this endpoint for a PC silent over 3 days), `disk` `{captureBytes, freeBytes}`, and `recorder` `{state, gameVersion, layoutOk, layoutReason, lastChunkAt, updatedAt}` or null. Times are ISO.                                                                                                                                                                                                                                                                                                                                                                                     |

Unknown ids return 404. Lat/Lon in traces are the sim's coordinates. Real metres, but placed around a fake origin; apply `georef` (`src/analysis/geo.ts`) to put them on the real map.

## Upload endpoint (`/api/upload`, `uploadApi`)

The authenticated write side for PCs without Admin credentials (the BotRacing tray, `tools/sessions/storeClient.mjs`). Rules and limits: `functions/src/uploadCore.ts`; tests: `node --test functions/test/uploadCore.test.mjs`. Every request carries `Authorization: Bearer <Firebase ID token>`. The owner comes only from the token: `users/{uid}.ownerKey` if an admin set it (Botkin's is `botkin`; never writable from any endpoint, and Firestore rules still deny all clients), else the uid.

| Call                                                          | Does                                                                                                                                         |
| ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /me`                                                     | `{ownerKey}`                                                                                                                                 |
| `GET /doc/{coll}/{id}`                                        | A doc, coll in `tracks`, `trackBoundaries`, `sessions`. `tracks` and `trackBoundaries` are shared app data, the same for every signed-in user. A session is 404 for another owner. |
| `POST /docs/write` `{ops}`                                    | `set` (with `merge`) or `delete`, up to 400 ops, coll in `recordings`, `sessions`, `laps`. A `tracks` or `trackBoundaries` op is refused `403 track data is curated, not uploaded` (and, being all or nothing, so is the whole request). 204. |
| `POST /docs/update` `{ops}`                                   | Merge `series`, `eventId`, `event` into existing sessions/recordings. `{failed}` lists missing ones.                                         |
| `GET /laps?sessionId=`                                        | `{ids}` of this owner's laps                                                                                                                 |
| `GET /file/md5?dest=`                                         | `{md5}` (base64) or `null`                                                                                                                   |
| `POST /file/upload-url` `{dest, contentType, gzip, size}` | A signed Storage URL (15 min) for the server-built path, with the headers to send; Storage refuses a body over `size` (max 200 MB). The client gzips first. The size counts toward usage when the URL is issued. |
| `GET /file?dest=`, `DELETE /file?dest=`, `GET /files?prefix=` | Read, remove, list. 404 when absent.                                                                                                         |
| `POST /heartbeat` `{hostId, label, version, lmuFound, state, ...}` | The tray's status for Settings, stored as `uploaders/{ownerKey}__{hostId}` with `ownerId` and the server's `lastSeenAt` (never taken from the body). Fields: `label` (64), `version` (32), `lmuFound`, `state` (`idle`, `waiting-for-game`, `in-game`, `syncing`, `retrying`, `error`), `lastUploadAt`, `lastSessionId`, `queue`, `progress` `{done, total, phase?}`, `retryAt`, `sessionsDone`, `problems` (up to 10 of `{kind, at, message (120), sessionId?, count?, retryAt?}`, each rebuilt from those fields; tokens and addresses in `message` are replaced), `disk` `{captureBytes, freeBytes}`, `recorder` `{state, gameVersion, layoutOk, layoutReason, lastChunkAt, updatedAt}`; `label`, `version`, `lmuFound`, `state` are required; unknown fields are dropped; `hostId` follows the id rule. 204. A host may write at most once per 30 s: sooner is `429` with `Retry-After` (seconds), and the tray sends its latest state after the wait. Counted as a heartbeat, not as a document or bytes. |

Where things land: `recordings`, `sessions` and `laps` stay top-level with `ownerId` (the readers filter on it); an existing doc with another `ownerId` is never read, written or deleted by someone else (a read is 404). Track data (`tracks`, `trackBoundaries`, and the surface and outline files they name) is app data in the shared `tracks/` docs: curated by Botkin only, written by the admin tools, never by an upload, and read by every signed-in user. Bucket paths `traces|bands|field|slices/{ownerKey}/...` must carry the caller's own key; `archive/...` is stored as `archive/{ownerKey}/...` (unchanged for `botkin`). Usage per uid (`docs`, `docBytes`, `files`, `fileBytes`) is counted server-side on `users/{uid}.usage`.

## Who is asking (read API)

Every `/api/lmu` response is for one owner. `Authorization: Bearer <Firebase ID token>` is verified; the owner is `users/{uid}.ownerKey` if an admin set one, else the uid (same rule as the upload endpoint). A bad or expired token is `401`. **A request with no Authorization header is `401`**: every read needs a signed-in owner (`ANONYMOUS_OWNER` in `functions/src/ownerAccess.ts` is `null`). Sessions and laps are filtered by the owner; a session, lap or file of another owner is a `404`. Track maps are shared and the same for everyone. Stored files named by a session doc (band, field, corner slices) are only served from that owner's own folder (`bands|field|slices/{owner}/...`). A session's track map, surface and outline come from the shared track docs, whose file paths are trusted because only the admin tools write them. `/uploaders` lists only the owner's own machines (their heartbeats carry the owner; the old ownerless docs are shown to nobody). Responses are `Cache-Control: private` and vary on `Authorization`.
