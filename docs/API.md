# Lap API

One Cloud Function, `dataApi`, behind Hosting at `/api/{sessions,laps,tracks,plan,uploaders}` (no sim in the path: `sim` is a query parameter where it matters). The old `/api/lmu/**` still answers through the function `lmuApi` (the same handler) until every installed client, Android before its OTA update and old tools, is updated; then the route and `lmuApi` are deleted (roadmap row). It reads only; the PC uploader (`tools/sessions/sync.mjs`) writes. Storage layout: `docs/STORAGE.md`.

## Upload endpoint (`/api/upload`, `uploadApi`)

The authenticated write side for PCs without Admin credentials (the BotRacing tray, `tools/sessions/storeClient.mjs`). Rules and limits: `functions/src/uploadCore.ts`; tests: `node --test functions/test/uploadCore.test.mjs`. Every request carries `Authorization: Bearer <Firebase ID token>`. The owner comes only from the token: `users/{uid}.ownerKey` if an admin set it (Botkin's is his own uid, as `users/{uid}.ownerKey` reads on 2026-10-31; never writable from any endpoint, and Firestore rules still deny all clients), else the uid. Every response carries `Cache-Control: no-store`: Hosting's CDN otherwise keeps a 404 for ten minutes, and a session read before it was written would answer "no such document" to its own read-back (ticket 80).

## Hand-off to the app's 3D page (`POST /api/auth/handoff`, `handoffApi`)

The Android app shows the 3D in a WebView of the web race page (`/session/{id}/race?embed=3d`) and signs that page in as the same person without asking again. `Authorization: Bearer <Firebase ID token>`, verified with `checkRevoked`; the answer is `{token}`, a Firebase custom token for **that** uid, and nothing else. Nothing in the request chooses the user (the body and query are ignored). `no-store`, never logged; at most 10 a minute per uid (`429`); a missing, bad or revoked token is `401`; only `POST`. The page takes the token from the address fragment (`#ct=`, never sent to a server) and removes it at once. Rules `functions/src/handoffCore.ts`, binding `handoffApi.ts`, counts in `handoffLimits/{uid}` (Admin-only).

## Fuel presets (`GET` and `PUT /api/fuel-presets`, `fuelPresetsApi`)

His fuel-planner rule sets follow him between devices (`src/features/plan/presetSync.ts`; storage: `docs/STORAGE.md`, `fuelPresets/{ownerKey}`). Same sign-in and owner as the read API; `Cache-Control: no-store`.

- `GET` gives `{presets, removed, version, updatedAt}`: `{presets: [], removed: {}, version: 0, updatedAt: null}` before anything was written.
- `PUT {presets, removed, baseVersion}` writes the whole list if `baseVersion` is the stored `version`, in one transaction, and answers `200` with the new doc (`version` + 1). A write built on an older version is **`409` with the current doc** and stores nothing: the client merges it into its own list and writes again. Caps: at most 50 presets; each is typed field by field (`id`, `name` 1 to 80 characters, `length` `{kind: 'laps' | 'min', value}`, `fuelL` or null, `vePct`, `veRatio` or null, `formationLap`, `mandatoryStops` 0 to 20, `savedAt` ISO); unknown fields are dropped; a tombstone older than 90 days is dropped on write, at most 200. A bad body is `400` with the reason; no or a bad sign-in is `401`; any other method `405`.
- The merge is the client's (`src/state/presetMerge.ts`): a preset on one side only is kept; the same id with different content is merged against what the device last saw of the account (`synced`: id to `savedAt`): a device that did not edit it takes the account's edit, a device that edited it while the account did not keeps its edit, and only when both moved (or nothing is known) are both kept (the newer `savedAt` keeps the id, the other becomes a "(copy)"); a tombstone beats an older preset (times compared as times), a preset saved after its removal wins. Another person signing in on the device gets their own list; the first person's, pending or not, is kept under their uid and restored when they come back.

## Who is asking (read API)

Every `/api` response is for one owner. `Authorization: Bearer <Firebase ID token>` is verified; the owner is `users/{uid}.ownerKey` if an admin set one, else the uid (same rule as the upload endpoint). A bad or expired token is `401`. **A request with no Authorization header is `401`**: every read needs a signed-in owner (`ANONYMOUS_OWNER` in `functions/src/ownerAccess.ts` is `null`). Sessions and laps are filtered by the owner; a session, lap or file of another owner is a `404`. Track maps are shared and the same for everyone. Stored files named by a session doc (band, field, corner slices) are only served from that owner's own folder (`bands|field|slices/{owner}/...`). A session's track map, surface and outline come from the shared track docs, whose file paths are trusted because only the admin tools write them. `/uploaders` lists only the owner's own machines (their heartbeats carry the owner; the old ownerless docs are shown to nobody). Responses are `Cache-Control: private` and vary on `Authorization`.
